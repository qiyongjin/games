# 弈步 · 中国象棋

在对弈中认识象棋：点击“下一步”让电脑应手、随局讲解、可拖动规则窗口，以及通过邀请链接与好友对弈。手机与电脑使用相同的木色棋盘、圆形棋子与绿色界面，小屏按宽度缩放并纵向排列。

项目使用 Node.js 内置模块，无需安装第三方运行依赖。**访问统计、后台和好友对弈需要 Node 服务，不能只上传静态 HTML。**

## 本地运行

需要 Node.js 20 或更新版本，部署镜像使用 Node.js 22。

```sh
npm run dev
```

打开 <http://127.0.0.1:5173>，管理后台为 <http://127.0.0.1:5173/admin>。修改服务端代码后需要重启进程。请通过 HTTP 服务打开页面，直接双击 HTML 无法加载模块、Worker 和 API。

首次启动会生成独立管理员密码，保存在 `DATA_DIR/admin-credentials.txt`；默认目录是运行命令所在目录的 `.data/`。启动日志只提示文件位置。请在服务器上读取该文件并自行保管密码，页面没有管理员注册入口。

## 拉取、构建与部署

`xiangqi.qyjai.com` 的专用 systemd 与 Nginx 配置见 [deploy/README.md](deploy/README.md)，构建时会一同放入 `dist/deploy/`。适用于已有 Node.js 22 和 Nginx 的 Alibaba Cloud Linux 3。

在服务器拉取已提交的代码后，进入仓库的 `xiangqi` 目录执行：

```sh
git pull
npm test
npm run build
export HOST=127.0.0.1
export PORT=5173
export DATA_DIR="$PWD/.data"
export TRUST_PROXY=1
npm run start:prod
```

以上适用于同机 Nginx 反代的 Linux 服务器。直连 Node 进行本机测试时不设置 `TRUST_PROXY`。Windows PowerShell 可使用 `$env:PORT='5173'` 等方式设置变量。

构建产物在 `dist/`，包含前端文件和 Node 服务，可独立上传：进入 `dist/` 后执行 `npm start`。统计数据与管理员凭据不会被打包；独立上传部署时应将 `DATA_DIR` 设置为构建目录之外的持久化目录。更新代码时停止旧进程、重新构建并重启；可用 systemd 或其他进程管理器保持服务运行。

生产环境通过 **HTTPS** 访问。Node 端口保持只对本机可见，由现有 HTTPS 站点转发所有路径（包括 `/api/` 与 `/admin`）：

```nginx
location / {
    proxy_pass http://127.0.0.1:5173;
    proxy_http_version 1.1;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_read_timeout 30s;
}
```

反代必须**覆盖**访客传入的转发头，尤其是上面的 `X-Forwarded-For $remote_addr`。`TRUST_PROXY=1` 仅用于此类受控反代；不要同时将 Node 端口直接暴露给公网。HTTPS 反代会使后台会话 Cookie 带有 `Secure` 标记。

### Docker 部署

项目已包含 `Dockerfile` 与 `compose.yaml`，在项目目录执行：

```sh
docker compose up -d --build
docker compose exec xiangqi cat /data/admin-credentials.txt
```

Compose 默认只映射 `127.0.0.1:5173`，配合上述 HTTPS 反代使用。`xiangqi-data` 命名卷保存统计与密码，重建镜像不清除数据。升级时拉取代码后再次运行 `docker compose up -d --build`。请备份该卷；不要在保留数据时使用 `docker compose down -v`。

### 配置

| 环境变量 | 默认值 | 作用 |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | Node 监听地址；Docker 容器内为 `0.0.0.0` |
| `PORT` | `5173` | 监听端口 |
| `DATA_DIR` | 当前工作目录下 `.data/` | 可写的持久化目录 |
| `ADMIN_PASSWORD` | 首次随机生成 | 可选，12–256 字符；启动时覆盖已有密码散列 |
| `TRUST_PROXY` | 不信任 | 只有值为 `1` 才读取反代设置的访客 IP 和 HTTPS 协议 |

忘记密码时，可在服务器通过环境变量设置新的 `ADMIN_PASSWORD` 并重启。重启会使原会话失效。管理员密码使用 scrypt 散列校验；初始凭据文件仅供首次取出密码，妥善保存后可以自行移出数据目录。

## 管理后台与统计口径

访问你的站点 `/admin`，输入管理员密码。后台提供：访问次数、浏览器访客数、玩过人数、完局人数、开局数、完局数、在线人数，以及访客/IP/浏览器信息、对局记录、优化建议。

- 未登录不能读取统计、建议或 IP 查询接口。管理会话使用 HttpOnly、SameSite=Strict Cookie，12 小时到期；登录有限速，同源校验保护写入操作。
- 每次加载游戏页面记一次访问；心跳只更新在线状态。人数按浏览器访客标识估算，同一 IP 可能多人共用，清除 Cookie 或更换设备可能重复计数。
- 人机对局首次落子记开局，提交完整合法终局记录才记完局；重复上报不会重复计数。好友对局在双方在线且均准备时记开局，终局或主动离开时记完局；断线等待与服务重启导致的中断不算正常完局。
- IP 溯源显示 IPv4/IPv6、网络范围及可获得的 PTR 主机名，用于排查网络来源，不能确定真实个人身份或精确地址，不会将访客 IP 发送给第三方定位服务。
- 数据保留最多 90 天，容量上限为 1 万访客、2 万棋局、2 千条建议；超过上限保留较新的记录。访客行显示最近 IP，对局记录保留参与 IP。页面底部有统计告知。

`.data/`、`.env*`、构建产物和日志均加入忽略规则，静态服务仅提供公开资源白名单，不能通过网址下载凭据、统计文件、测试或服务端源码。

## 好友对弈

1. 点击顶部“邀请好友”，创建新棋局并复制邀请链接。
2. 好友用自己的浏览器打开链接，创建者执红，受邀者执黑。双方需要能访问同一个服务器域名。
   双方界面都会标明红黑身份，棋盘始终以己方在下、对方在上的视角显示；执黑时列号、合法落点和方向键一起随视角调整，棋子文字保持正向。走棋记录统一使用红方视角的固定坐标。
3. 两人都在线并分别点击“准备开始”后开局，红方先行。每次落子由服务端校验席位、轮次、盘面版本和象棋规则。
4. 页面约每 1.5 秒同步；断线超过 45 秒会暂停落子。同一浏览器再次打开原邀请链接时，会识别原来的红方或黑方，恢复席位与盘面；重新打开标签页也可继续。若原席位由其他用户占用，会弹窗提示并提供“重新邀请好友”入口，临时离线不会让第三人替换席位。分享的邀请链接不包含席位凭据；更换浏览器、设备或清除浏览器身份数据后，无法识别为原玩家。
5. “返回电脑对弈”会离开好友棋局；已开始的对局按离开方认输处理。电脑对局原有进度会恢复。
6. 胜负或和棋后弹出“再来一局 / 退出”。先点击“再来一局”的一方发起邀请，另一方收到“对方邀请您再来一局”，选择“继续对弈”后双方在原房间开始新一局，保留红黑身份。两人同时点击时由服务器确定先发起者，另一方仍需明确同意；退出会取消邀请。刷新页面可恢复结果与邀请状态，每一局分别统计。

当前为单进程房间服务，房间空闲 6 小时或创建超过 24 小时会过期。统计持久化，在线房间保存在内存中，服务器重启后需重新邀请。请使用单实例部署；多实例需要共享房间状态后才能扩容。

## 电脑对弈与规则

- 点击自己的棋子，再点击落点。圆点表示可移动，圆环表示可吃子。红方走完后，点击“下一步 · 电脑落子”才让电脑走一步；教学开关不影响这一操作。
- 人机与好友对局都会标记最近一步：走前的位置较暗，走后的位置较亮，棋盘下方同时显示起点到落点的记录，方便看清双方如何行棋。
- 吃子后在棋盘下方提示“你吃掉了对方的×”或“对方吃掉了你的×”，按当前红黑身份显示，关闭教学也可见；走棋记录保留每次吃子的提示，悔棋或重新开始会同步更新。
- 人机模式可以提示、悔棋和重新开始；好友对弈中不提供单方悔棋和电脑提示。
- 人机对局结束也会弹出结果，可点击“再来一局”直接重新开始，或点击“退出”关闭结果窗口、保留终局棋盘。
- “走棋记录”可回看讲解；“规则速查”可拖动标题、展开和收起，浏览器会记住位置。
- 人机对局、教学与难度设置保存在当前浏览器；刷新或从好友棋局返回后若轮到电脑，仍需点击“下一步”继续。
- 棋盘支持方向键移动焦点、回车选子/落子、Esc 取消。规则浮窗标题也可用方向键移动。
- 有效落子时播放内置的“碰撞.mp3”音效（`assets/move-collision.mp3`，使用用户上传的原始音频），自己、电脑和好友的落子均适用；选子、非法走棋、提示和恢复历史记录不会播放。棋盘下方可开关音效，浏览器会记住设置；重新开启时会播放该音效供试听，方便在 iPhone 微信内置浏览器中直接触摸解锁和检查声音。首次点击、触摸结束或按键时会解锁声音，并可在音频被系统暂停后通过再次操作恢复。若仍无声，请检查系统静音模式和媒体音量。

## 立体棋盘与对局演出

棋盘采用 CSS 3D 透视与木质厚度，棋子保留可辨识的正向文字。车突进、马踏风跳跃、象腾起落地、士回旋、将帅升起推进、炮抛物线轰击、兵短跃踏步；每类棋子也有各自的待机效果。吃子时，被吃棋子飞散并出现粒子与「哥们，菜你就多练」台词；将军时显示独立提示。人机和好友对局均在真实新增落子时触发，刷新恢复、重复同步和查看历史不会重播。悔棋、重开和切换对局会清理演出；系统启用“减少动态效果”时保留文字提示、跳过位移动画。

吃子语音使用设备的中文语音合成能力；不提供中文语音或朗读失败时保留文字提示。《关中王进行曲》已内置为 `assets/check-march.m4a`，使用用户提供的原始 AAC 音轨。真实新增落子形成将军时，从头循环播放；对方应将、解除威胁后，音乐在约 1.5 秒内逐渐减弱至停止。再次将军会取消尚未完成的淡出并重新播放。刷新恢复或重复联机同步不会重播；静音、悔棋、重开和切换对局会立即停止旧配乐。

展开棋盘下方的“对局声效”可试听内置配乐，也可临时选择本地音频替换；点击“恢复内置配乐”切回默认音乐，本地替换不上传且刷新后重置。声音开关同时控制落子声、吃子语音和将军配乐；浏览器限制播放时可先点“试听配乐”。音乐随源码、独立构建包和 Docker 镜像一起提供，`git pull` 后无需另行选择或下载。

包含马腿、象眼、炮架、河界、九宫、将帅照面、应将、将死与困毙。重复局面采用教学休闲规则：同一盘面与轮走方第 4 次出现时，重复区间仅一方每步将军则该方判负，其余判教学和棋；不裁定复杂长捉。

基础行棋依据：[世界象棋联合会《世界象棋规则》](https://www.wxf-xiangqi.org/images/wxf-rules/2018_World_Xiangqi_Rules_Chinese_2018.pdf)。

## 验证与结构

```sh
npm test
npm run build
```

测试覆盖规则、搜索、讲解、存档、悔棋、后台鉴权与会话、路径泄漏、统计幂等与保留期、联机准备/轮次/非法走棋/断线和重启。

- `src/engine.js`、`src/session.js`：共享规则与对局状态，浏览器与服务端复用。
- `src/app.js`、`src/network.js`：界面、电脑对弈、联机同步和统计上报。
- `src/feedback.js`、`src/admin.js`：优化建议与管理员界面。
- `scripts/server.mjs`、`scripts/storage.mjs`：HTTP API、鉴权、房间与持久化。
- `scripts/build.mjs`：生成独立运行包；不复制数据或密钥。
